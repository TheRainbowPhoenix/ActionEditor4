## Tile collision rule

`GetTileCollisionAttribute` at `0x45E4F0`:

- returns `0` when tile animation/trigger conditions hide the tile
- returns `0` when `tile+107 == entity+120`
- otherwise returns `*(uint8_t *)(tile+106)`

So tile collision byte is `TileEntry+106`, category/ignore group is `TileEntry+107`.

`World_CheckTileCollision` at `0x40CB10` converts world coordinates using:

- `tile_x = x >> 5`
- `tile_y = y >> 5`
- `tile_idx = tile_x + (tile_y << scene[27])`

It samples `entity+475 + 1` points along the queried edge and returns the tile index with the highest collision attribute, using center proximity as tie-break for horizontal scans.

## Player `vtable+68` / `0x4A1200`

Runtime player vtable `+68` is `0x4A1200`. It is the X movement/update method:

- if `entity+0x288` / `double[81]` is nonzero, it copies that impact/speed override into `entity+0xB0` (`speed_x`) and logs `MoveX()`
- otherwise, if `entity+0xC0` is nonzero, it decays that field through `sub_49E920`
- then it adds `entity+0xC0` into `entity+0xB0`
- it clamps `entity+0xB0` to `+-dbl_5A9820`
- it adds `entity+0xB0` into `entity+0x80` (`x_min`)
- it calls vtable `+0x3C` to refresh derived bounds

Important field observations:

- `entity+0x80`: `x_min`
- `entity+0x88`: `y_min`
- `entity+0x90`: `x_max`
- `entity+0x98`: `y_max`
- `entity+0xB0`: `speed_x`
- `entity+0xB8`: `speed_y`
- `entity+0xC0`: X acceleration/impact accumulator used by `0x4A1200`
- `entity+0xC8`: Y acceleration/impact accumulator used by `0x4A13B0`
- `entity+0xD0`: decay amount used by `sub_49E920`
- `entity+0x288`: X impact override
- `entity+0x290`: Y impact override
- `entity+0x2A0`: previous Y impact snapshot, used by `Entity_FoldImpactYIntoSpeed` to avoid re-adding unchanged `impact_y`
- `entity+0x530`: MoveX modifier mode; when enabled and equal to `3`, MoveX applies an extra decay adjustment
- `entity+0x538`: MoveX modifier factor; MoveX uses `(factor - 1.0)` multiplied by `Physics_ScalarPerFrame60(speed_scalar)`
- `entity+0x540`: MoveX modifier enabled flag

`0x4A13B0` is the paired Y movement/update method:

- calls `sub_46A3B0` first to fold Y impact into `speed_y`
- applies `entity+0xC8` when enabled
- calls `sub_49E820`, which clamps `speed_y`, adds it into `y_min`, then calls collision-ish `sub_49E1E0`
- refreshes bounds via vtable `+0x40`

`sub_46B130(input)` does not read only the two visible input masks. It scans ten per-direction/per-button state records at `input+0x210`, populated by `Input_UpdateHoldCounters` and `Input_UpdateStateBuffer`. Replay must inject masks before `Input_UpdateHoldCounters`; injecting only after `Input_UpdateStateBuffer` leaves those derived records stale and does not move the player.

## First-pass entity/motion struct map

`struct_this_move` and `struct_this_movey` are partial IDA views of the same entity object. The object is not just a movement component; it carries render bounds, motion, collision shape data, action vectors, contact flags, and input-derived command state.

Core position and motion:

- `+0x000`: vtable
- `+0x080`: `x_min` / world X left
- `+0x088`: `y_min` / world Y top
- `+0x090`: `x_max` / world X right
- `+0x098`: `y_max` / world Y bottom
- `+0x0B0`: `speed_x`
- `+0x0B8`: `speed_y`
- `+0x0C0`: X accel/impulse accumulator, decayed by `sub_49E920`
- `+0x0C8`: Y accel/impulse accumulator
- `+0x0D0`: decay amount used by `sub_49E920`
- `+0x0E0`: enable decay for `+0x0C0`
- `+0x0E4`: enable decay for `+0x0C8`
- `+0x0F0`: object height used by `sub_49E1E0` world-bound clamp
- `+0x0FC`: axis/form mode; `0` normal/horizontal, `1+` alternate axis behavior
- `+0x100`: axis subtype byte used with `+0x0FC`
- `+0x288`: `impact_x`; if nonzero, `MoveX` copies this directly into `speed_x`
- `+0x290`: `impact_y`; folded into `speed_y` by `sub_46A3B0`

Identity/input/action:

- `+0x070`: player-controlled flag; if set, command code uses input device 0
- `+0x078`: tile collision ignore/category id passed to `GetTileCollisionAttribute`
- `+0x1D3`: input device index for non-player entities
- `+0x1D6`: entity form/type byte updated by `0x4A14B0`
- `+0x1DB`: collision edge sample count minus one; `World_CheckTileCollision` samples `+1`
- `+0x21C`: active command/action vector header; entries appear to be 136 bytes
- `+0x220/+0x224`: active command/action vector begin/end, depending on IDA type view

Screen/sprite/collision dimensions:

- `+0x03C..+0x048`: screen-space AABB from `Entity_UpdateBoundingBox`
- `+0x04C`: sprite/draw offset X
- `+0x050`: sprite/draw offset Y
- `+0x054`: sprite width
- `+0x058`: sprite height
- `+0x0EC/+0x0F0`: tile sample step X/Y copies used by edge sampling
- `+0x470/+0x474/+0x478/+0x47C`: main collision box offset X/Y and width/height
- `+0x480/+0x484/+0x488/+0x48C`: second copy of main collision box offset X/Y and width/height
- `+0x4B0/+0x4B4/+0x4B8/+0x4BC`: secondary box offset X/Y and width/height
- `+0x570/+0x574/+0x578/+0x57C`: attack/hit box offset X/Y and width/height
- `+0x590..+0x598`: vector/list of derived/sorted box descriptors rebuilt by `0x4A0A30`

Contacts and collision state:

- `+0x2A8`: collision/gravity suppression flag used by `Entity_ApplyGravity`
- `+0x2AC`: current floor tile pointer from floor check
- `+0x2B0`: in-air flag
- `+0x2B4`: floor/landed tile pointer copy
- `+0x2C4`: air-time counter
- `+0x2D4`: transition/form timer set by `0x4A14B0`
- `+0x2D8/+0x2DC/+0x2E0/+0x2E4`: left/right/top/bottom contact flags used by restore/collision paths
- `+0x32C`: standing parent/platform pointer or flag; suppresses gravity when nonzero

Movement helpers:

- `0x4A1200`: MoveX, `speed_x/impact_x`
- `0x4A13B0`: MoveY, `speed_y/impact_y`
- `0x49E920` `Entity_DecayScalarTowardZero`: scalar decay toward zero by `entity+0xD0`
- `0x49FAA0` `Physics_ScalarPerFrame60`: converts a scalar by `value / g_friction_constant / 60`
- `0x49E820` `Entity_ApplyVelocityYAndClamp`: clamp/add `speed_y` to `y_min`, then world-bound check
- `0x49E1E0`: world-bound clamp/status, not tile collision
- `0x49DCD0` `PlayerEntity_SetMovementAxisModeFromForm`: maps form state to `movement_axis_mode +0xFC` and `movement_axis_subtype +0x100`

`ActionSet_BuildRuntimeCommands` turns raw 112-byte action records into runtime 136-byte command records. For each raw command, it:

- writes the raw command pointer to runtime `+0x00`
- computes default `runtime+0x08 = 6 * g_physics_substeps * (raw+0x58 + form_variant * raw+0x5A)`
- if raw detail pointer `raw+0x48` exists, computes `runtime+0x20` from detail speed fields divided by `g_frame_rate_constant_60`, optional `runtime+0x78`, and `runtime+0x10` from detail `+0x25`
